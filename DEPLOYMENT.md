# Deploying SnapTick (free tier)

| Part | Host | Notes |
|---|---|---|
| Client (React) | **Vercel** | Static build, SPA rewrite in `Frontend/vercel.json` |
| API (Node/Express) | **Render** free web service | `render.yaml`; sleeps after ~15 min idle |
| Face service (InsightFace) | **Hugging Face Space** (Docker) | `deepface-hf/`; CPU, ~1 GB RAM |
| Database | **MongoDB Atlas** M0 | Holds everything, including student photos (GridFS) |

Deploy in this order: database → face service → API → client.

---

## 1. MongoDB Atlas

1. Create a free **M0** cluster.
2. *Database Access*: add a user with a strong password.
3. *Network Access*: add `0.0.0.0/0` (Render's outbound IPs are not fixed on the free plan).
4. *Connect → Drivers*: copy the connection string and put the database name in it:
   `mongodb+srv://USER:PASSWORD@cluster.xxxxx.mongodb.net/snaptick?retryWrites=true&w=majority`

### Moving existing local data (optional)

Student photos are already stored inside MongoDB, so one dump carries everything:

```bash
cd Backend && node scripts/migrate-photos-to-db.js   # only needed once for old installs
mongodump --uri "mongodb://localhost:27017/snaptick" --out /tmp/snaptick-dump
mongorestore --uri "<ATLAS URI>" --nsInclude 'snaptick.*' /tmp/snaptick-dump
```

The embeddings were produced by the same InsightFace model the Space runs, so no re-enrolment is needed.

## 2. Face service on Hugging Face

```bash
./deepface-hf/sync.sh
```

Create a new Space → SDK **Docker** → upload `README.md`, `Dockerfile`, `requirements.txt` and `app.py`
from `deepface-hf/`. The first build takes ~10 minutes (the model is downloaded during the build).
Check `https://<user>-<space>.hf.space/health` returns `{"status":"ok", "model":"insightface-buffalo_l", ...}`.

Free Spaces sleep after 48 h without traffic and need about a minute to wake up.

## 3. API on Render

*New → Blueprint* and select this repository (uses `render.yaml`), then set:

| Variable | Value |
|---|---|
| `MONGO_URI` | Atlas URI from step 1 |
| `DEEPFACE_URL` | Space URL from step 2 (no trailing slash) |
| `BASE_URL` | the Render URL, e.g. `https://snaptick-api.onrender.com` |
| `ALLOWED_ORIGINS` | the Vercel URL(s), comma-separated |
| `ALLOWED_EMAIL_DOMAINS` | e.g. `abes.ac.in` to restrict sign-ups (optional) |

`JWT_SECRET` is generated by the blueprint, `NODE_ENV=production` and `TZ=Asia/Kolkata` are preset.
The server refuses to start without `JWT_SECRET` in production.
Check `https://<render-url>/health` returns `{"api":"ok","database":"ok","faceService":"ok"}`.

## 4. Client on Vercel

Import the repository, set **Root Directory** to `Frontend`, framework **Vite**, and add
`VITE_API_URL=https://<render-url>`. After the first deploy, add the Vercel URL to
`ALLOWED_ORIGINS` on Render.

## Before a lecture

Open the app a minute early. The sidebar shows *All systems online* once the API, database and
face service are awake; until then it shows what is still starting.

## What persists where

- **MongoDB**: accounts, classrooms, students, embeddings, attendance and student photos.
- **API disk (temporary)**: annotated scan images and face crops, deleted after 10–30 minutes.
  A restart during a review only means the review must be repeated.
